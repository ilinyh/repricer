# Repricer — прототип репрайсера для маркетплейса

Репрайсер сам двигает цену товара маленькими шагами по запасу в днях: поднимает, если товар
скоро кончится, снижает, если залёживается, и не выходит за коридор базовой цены и минимальную
маржу. Площадка — эмулятор Wildberries с реальными путями и форматами API. Источник учёта —
CSV или живая 1С:УТ 11 по OData.

## Стек и почему

- **Python 3.12+** — денежная арифметика на `Decimal` и целых копейках без плавающей точки,
  ядро легко покрывается табличными тестами.
- **FastAPI + Jinja2/HTMX-минимум** — один процесс, серверный рендеринг, нет сборки фронтенда.
- **SQLite (стандартная библиотека)** — одному пользователю хватает, нет лишних зависимостей.
- **Эмулятор — отдельный FastAPI-сервис**, общается с репрайсером только по HTTP.
- **pytest** — ядро, адаптеры, конвейер, веб-интерфейс.

## Запуск

### Одной командой (Docker)

```bash
docker compose up --build
```

- Репрайсер: http://localhost:8080
- Эмулятор WB: http://localhost:8090 (проверка: `GET /health`)

Оба сервиса стартуют с демо-данными из CSV, без 1С. В интерфейсе нажмите «Пересчитать сейчас».

### Локально без Docker

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[dev]"
.venv\Scripts\python -m uvicorn emulator_wb.app.main:app --port 8090   # терминал 1
.venv\Scripts\python -m uvicorn repricer.web.main:create_app --factory --port 8080  # терминал 2
```

Переменные окружения — см. `.env.example`.

### Демо-данные

```powershell
python scripts/gen_demo_data.py       # CSV учёта + товары эмулятора (16 товаров)
python scripts/gen_goods_from_1c.py   # товары эмулятора из живой 1С (опционально)
```

В `data/products.csv` и `data/sales.csv` — 17 товаров, покрывающих все зоны, оба ограничителя
коридора, блокировку по марже, предупреждение о марже, отсутствие остатка и продаж, ровно
граничные 14 и 60 дней, мелкий шаг и скидку площадки. Один товар намеренно отсутствует на площадке.

## Сквозной сценарий (что показать)

1. Открыть http://localhost:8080 — таблица со зонами, ценами, маржой и причинами.
2. Переключить режим товаров на «рекомендация» (можно и «авто»).
3. «Пересчитать сейчас» — рекомендации встают в очередь (повторный прогон дубли не создаёт).
4. «Очередь» — подтвердить выбранные или все.
5. «Отправить одобренные» — пачка уходит в эмулятор.
6. «Обновить статусы» — «отправлено» → «применено»; ошибки и карантин видны в журнале карточки.
7. Карточка товара — журнал решений и изменений цены.

## Архитектура

```
источник учёта (CSV / 1С OData) ─┐
                                 ├─► ядро decide() ─► решения (SQLite) ─► очередь / авто
площадка (эмулятор WB / WB) ─────┘                          │
                                                            ├─► отправка пачкой (upload/task)
                                                            └─► polling статусов → журнал
веб-интерфейс (таблица, очередь, карточка, настройки) ──────┘
```

- `src/repricer/core/` — чистое ядро: `decide()`, типы, деньги. Без ввода-вывода, без часов, без БД.
- `src/repricer/adapters/accounting/` — `csv_source.py`, `onec_odata.py`; интерфейс
  `AccountingSource`. Новый источник — новый адаптер, ядро не меняется.
- `src/repricer/adapters/marketplace/wb_client.py` — клиент WB; один код для эмулятора и боевого WB.
- `src/repricer/storage/` — SQLite: товары, режимы, решения, задачи площадки, append-only журнал.
- `src/repricer/app/` — `service.py` (прогон, очередь, отправка, polling), `pricing.py`
  (подбор цены до скидки), `scheduler.py` (пересчёт по расписанию).
- `src/repricer/web/` — FastAPI + шаблоны.
- `emulator_wb/` — отдельный сервис-эмулятор WB.

## Ключевые решения

- **Ядро — чистая функция.** Дата расчёта передаётся параметром, системные часы внутри не
  читаются: исторические данные считаются «на дату» без подмены часов.
- **Деньги.** Внутри — целые копейки, проценты — `Decimal`. Округление до рубля «в сторону шага»,
  на границе коридора — внутрь. Все 14 контрольных примеров приложения А сходятся один в один.
- **Модель цены WB.** Держим скидку неизменной и двигаем «цену до скидки»; фактическая цена =
  целая цена × (1 − скидка/100). Подбираем ближайшую достижимую цену, проверяем по ней коридор и
  маржу. В журнале видно и целевую, и фактическую цену.
- **Режимы.** «Выключен» по умолчанию — включение репрайсера само цены не меняет.
- **Идемпотентность.** Повторный прогон на тех же данных не плодит рекомендации: активная одна,
  с той же целью — пропуск, с другой — старая помечается заменённой. Одинаковая пачка в эмуляторе
  не создаёт вторую задачу (`alreadyExists`).
- **Пауза.** От последнего подтверждённого площадкой изменения; решения «в полёте» тоже
  учитываются. Для исторического расчёта учитываются только изменения, подтверждённые до даты расчёта.
- **Журнал.** Append-only: создание/замена рекомендации, подтверждение, отклонение, отправка,
  применение, ошибка, карантин, смена режима и настроек. «Цена не менялась» пишется только при
  смене состояния, чтобы повторные прогоны не засоряли журнал.

## Источники учёта

### CSV

`products.csv`: `vendor_code,name,stock_qty,cost,base_price`;
`sales.csv`: `vendor_code,date,qty`. Цены в рублях с копейками.

### 1С:УТ 11 по OData

`ACCOUNTING_SOURCE=1c`, параметры `ONEC_URL`, `ONEC_USER`, `ONEC_PASSWORD`.
Товары — «Номенклатура» (Артикул), остатки — `ТоварыНаСкладах/Balance`, продажи —
`ВыручкаИСебестоимостьПродаж`, цены — `ЦеныНоменклатуры` (срез последних): базовая —
«Розничная», себестоимость — «Себестоимость», при отсутствии — из продаж (`Стоимость / Количество`).

> Важно: в демо-базе во время работы **состав стандартного интерфейса OData был пуст** — `$metadata`
> отдавала 0 наборов. Лечится вызовом `УстановитьСоставСтандартногоИнтерфейсаOData(Состав)` с
> нужными объектами. Подробности — в `AI_NOTES.md`.

## Допущения

- Артикул продавца — ключ товара. Дубликаты артикулов в источнике пропускаются (первый побеждает)
  с предупреждением в логе.
- Себестоимость в 1С: сначала вид цены «Себестоимость», если пусто/ноль — из продаж
  (`Стоимость / Количество`). Стоимость и цены берутся с НДС — комиссии и НДС в прототипе не
  разносим, как и просило ТЗ.
- Одна цена на `nmID`, размеры не моделируются.
- Карантин в эмуляторе — порог `WB_QUARANTINE_PCT`; в основном демо-профиле 30 %, для показа
  карантина есть профиль с низким порогом.
- Эмулятор хранит товары и задачи в памяти (при старте читает JSON) — перезапуск сбрасывает историю задач.
- Дата расчёта по умолчанию `2024-03-31` (демо-данные исторические), задаётся `REPRICER_AS_OF`.
- Опции из §6 ТЗ (поставка в пути, возврат к базовой цене, возвраты, лимит запросов 429, второй
  маркетплейс) не реализованы — см. ниже.

## Что не успели и что дальше

- §6 ТЗ: поставка в пути, возврат к базовой цене, поправка на возвраты, `429` и повторные запросы,
  второй маркетплейс через тот же контракт адаптера.
- Видео сквозного сценария; вместо него — скриншоты в `docs/screenshots/`.
- Более аккуратная работа с 1С: кэширование метаданных, пагинация при больших объёмах, отдельный
  пользователь только для чтения.
- Нагрузочные проверки пачек, если каталог вырастет до десятков тысяч товаров.
