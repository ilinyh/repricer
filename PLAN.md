# Прототип репрайсера — план работ

## 1. Решения, зафиксированные с заказчиком

| Вопрос | Решение |
|---|---|
| Стек | Python 3.12+ / FastAPI / SQLite / Jinja2 + HTMX, pytest |
| Модель цены площадки | держим скидку, двигаем «цену до скидки»; в рекомендацию попадаем с точностью до десятых рубля |
| Текущая цена для шага | фактическая цена после скидки; базовая — только для коридора |
| Пауза | от последнего **подтверждённого** площадкой изменения; «в полёте» тоже блокирует; отсчёт от даты расчёта |
| Повторный прогон | одна активная рекомендация на товар, дубли не создаём, применённую цену не шлём повторно |
| Режим «Выключен» | диагностика показывается, рекомендация не создаётся |
| Журнал | append-only события; полный срез прогона — отдельная таблица |
| Дата расчёта | параметр; по умолчанию — последняя дата с продажами |
| Объём | режем по §2.8 ТЗ, что не успели — в README |
| 1С | адаптер на OData, состав OData задан в базе |
| Демо-каталог | 15–20 CSV-товаров, покрывающих все случаи; карантин — отдельным demo-профилем эмулятора |
| Язык UI | русский, один пользователь, без авторизации |

## 2. Архитектура

```
repricer/
  src/repricer/
    core/          # чистая функция: правила, деньги, причины (без БД, HTTP, часов)
    adapters/
      accounting/  # csv.py, onec_odata.py
      marketplace/ # wb_client.py (эмулятор и настоящий WB — один код)
    app/           # прогон, очередь, отправка, polling, планировщик
    web/           # FastAPI + Jinja2/HTMX
  emulator_wb/     # отдельный сервис-эмулятор WB, свой код и хранилище
  tests/           # unit ядра, contract адаптеров, e2e
  data/            # пример CSV на 15–20 товаров
```

Поток: источник учёта + площадка → снимок → `decide()` на дату → решения в БД →
(очередь | авто) → батч в эмулятор → polling задачи → статусы и журнал.

## 4. Ключевые решения ядра

1. Деньги — целые копейки, проценты — `Decimal`; никакой плавающей точки.
2. Порядок: нет остатка → нет продаж → зона → коридор → округление → маржа (только при снижении) →
   «цена не изменилась» → пауза.
3. Округление до рубля «в сторону шага»; на границе коридора — внутрь; после округления коридор
   проверяется ещё раз.
4. Маржа блокирует только снижение; проверка по точному отношению, не по округлённому проценту.
5. Даты — только от переданной даты расчёта, не от системных часов.

## 5. Настройка демо-базы 1С (выполнено)

- База: `http://localhost:8081/ut115` (УТ 11.5, файловая), логин `Администратор` без пароля.
- MCP-сервис: `http://localhost:8081/ut115/hs/mcp`, подключён в OpenCode как `ut115`.
- OData: `http://localhost:8081/ut115/odata/standard.odata/` — были пустые `$metadata` и 0 наборов.
  Причина — пустой состав стандартного интерфейса OData. Задан состав (номенклатура, склады, виды цен,
  характеристики, ключи аналитики, регистры `ТоварыНаСкладах`, `ВыручкаИСебестоимостьПродаж`,
  `ЦеныНоменклатуры`) вызовом `УстановитьСоставСтандартногоИнтерфейсаOData(Состав)`.
  Повтор при развёртывании: добавить объекты в состав и перепроверить `$metadata`.
- Запросы адаптера: `Catalog_Номенклатура`, `.../Balance?Period=datetime'...'`,
  `..._RecordType?$filter=Period ge datetime'...'`, `InformationRegister_ЦеныНоменклатуры_RecordType/SliceLast`.

## 6. Допущения

- Артикул продавца — ключ товара; дубликаты артикулов в источнике логируются и пропускаются.
- Себестоимость в 1С: сначала вид цены «Себестоимость», если пусто — из продаж (`Стоимость / Количество`).
- Базовая цена в 1С — вид цены «Розничная».
- Продажи и остатки — на дату расчёта; окно фиксированной длины, недостающие дни = 0.
- Одна цена на `nmID`, размеры не учитываем.
- Карантин в эмуляторе зависит от порога; основной demo-профиль — высокий порог, отдельный профиль — низкий.

## 7. Решения, принятые при реализации

Зафиксированы там, где ТЗ молчит.

| Тема | Решение |
|---|---|
| Цена до скидки | скидка площадки не меняется; двигаем цену до скидки, фактическая = цена × (1 − скидка/100). В рекомендации храним целевую, в отправке — фактическую; коридор и маржа проверяются по фактической |
| Отправка | одна пачка на все одобренные решения; повторная одинаковая пачка получает `alreadyExists: true` |
| Статусы площадки | `1` — в обработке, `3` — обработана; карантин распознаётся по `errorCode` или тексту ошибки |
| Пауза в историческом расчёте | учитываются только изменения, подтверждённые до даты расчёта (`resolved_at <= as_of`) |
| Режим «Авто» | решение сразу в статусе `auto`, видно в очереди с пометкой «авто», уходит без подтверждения; до отправки его можно отклонить |
| Автоотправка | галочка в настройках; после планового прогона планировщик отправляет подтверждённые и авто — как кнопка «Отправить одобренные» |
| Журнал «цена не менялась» | пишется только при смене состояния, повторные прогоны не засоряют журнал |
| Планировщик | поток внутри веб-процесса; интервал в минутах из настроек, `0` — выключен; занятый прогон пропускается; дата расчёта планового прогона — системное время (вне ядра) |
| Идемпотентность прогона | активные решения — `pending`, `approved`, `auto`, `sent`; совпавшая цель — пропуск, другая — замена (кроме `sent`: пока площадка не ответила, новую не создаём) |
| Массовое подтверждение | все отмеченные чекбоксы (`getlist`), «все» — отдельный вариант |
| 1С OData | параметры кодируются вручную: пробел — `%20`, литералы `datetime'...'` сохраняют кавычки; наименование — поле `Description`; `SliceLast` вызывается на `_RecordType` |
| Себестоимость 1С | цены и стоимость — с НДС, комиссии и НДС не разносим (как просило ТЗ) |
